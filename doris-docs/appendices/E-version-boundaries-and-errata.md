## E.1 本书分析的是什么版本

正文基于本地源码 `a53b182f810be2b3731c7dfdf6f40ff5a0ad63bd`，编写日期为 2026-10-12 至 2026-10-13。它是一个明确的源码快照，不等于已经核实的官方发布版本。官方文档用于概念与语法参考时，也不保证全部实现与这个快照完全相同。

第 22—24 章描述当前 Connector SPI 与扩展模块；查阅其他版本若发现类名或路径不同，应先比较版本演进，不能直接把旧文档判为错误。第 23 章区分普通数据扫描与系统表等分支；某一 Reader 存在，不证明所有格式、所有表都通过它。

## E.2 已覆盖与尚未穷尽

28 章正文 v1 已覆盖大纲的系统主线，并不意味着逐行分析全仓库或覆盖每一个能力。以下内容仍需要有针对性的专题与环境：

| 主题 | 当前覆盖 | 尚需补充的证据 |
|---|---|---|
| 查询与优化 | 代表性计划、规则、算子 | 更多 SQL 类型、统计偏差与实际 Profile |
| 更新与一致性 | 主要对象和状态边界 | 各写入模式、并发时序与故障实验 |
| 外表 | Iceberg 代表性路径 | 每种 Connector 的能力矩阵及真实外部系统 |
| 集成与扩展 | 方向、协议、生命周期 | 独立连接器版本与端到端恢复测试；具体 UDF 专题 |
| 存算分离 | 元数据、读写、回收路径 | 部署、容错、缓存及扩缩容实测 |
| 备份、复杂类型等 | 代表性入口和边界 | 按真实问题深入的子专题 |

出现“入口”意味着提供阅读起点；出现“源码核对”意味着核对文中代表性实现；只有明确记录命令、环境和结果才算运行验证。

## E.5 下一轮修订的优先级

优先补实际阅读中遇到的断点和运行证据，再扩展专题。比如先验证订单 SQL 的完整闭环，再比较一条外表查询的计划和扫描；若要贡献 FE 导入状态处理，则直接进入第 14、16、27、28 章，不必等待全书所有实验完成。

本书提供系统地图与源码入口。读者能独立解释行为、提出可复现问题、写出有效测试并回应 review，才是迈向持续贡献的成果；章节完成数不代表这些能力已验收。

## 2026-10-13 第二轮补写与勘误

第 3、17 章原先将 `OlapScanNode.updateScanRangeVersions()` 作为普通内表扫描版本入口，范围不准确。已改为普通路径 `addScanRangeLocations()` 读取分区 visibleVersion；批量更新方法属于 Cloud 路径。见[专题 1](../deep-dives/01-query-rpc-and-cancellation.md)。

九篇专题沿当前本地快照补写。IVM、Connector 结构、版本化 Cloud 元数据等只能据此判断当前源码，不能直接映射到某一发布版本。历史查询与历史修复分别有独立版本来源，均不标记为当前 HEAD 实测。
