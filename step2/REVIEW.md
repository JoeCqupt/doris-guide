-- 或 ORDER BY SUM(amount) DESC, city ASC

## 回答你提出的 Bitmap 问题

Bitmap 可以把非负整数编号当成位的位置：用户出现就把对应位设为 1，重复出现还是 1。两份集合做按位 OR 就能求并集，统计 1 的数量便得到去重人数。

例如只演示编号 0–4，按编号从左到右画位（不是二进制数的书写顺序）：

```text
编号       0 1 2 3 4
集合 X     0 1 0 1 0   → {1,3}
集合 Y     0 0 0 1 1   → {3,4}
X OR Y     0 1 0 1 1   → {1,3,4}
```

要满足两个条件：同一用户在所有节点映射到同一编号；不同用户映射到不同编号。直接把字符串哈希成整数可能碰撞，不能据此保证对原始用户精确去重。

你提出“Bitmap 中间结果就很少”是一个值得实验的假设，但不是普遍结论。普通位数组的空间和最大编号有关：两个相隔很远的编号也可能需要很长的位数组。Doris 的 Bitmap 精确去重使用 RoaringBitmap 相关实现，不能把 Java BitSet 的布局和内存结论直接套过去。HLL 是另一种近似统计思路，本次不展开。

参考：[Java BitSet API](https://docs.oracle.com/en/java/javase/26/docs/api/java.base/java/util/BitSet.html)、[Doris Bitmap 精确去重](https://doris.apache.org/docs/dev/query-acceleration/distinct-counts/bitmap-precise-deduplication/)。
