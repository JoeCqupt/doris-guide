# Job 001：从订单 CRUD 到分析查询

- 日期：2026-09-22
- 预计时间：45–60 分钟
- 交付位置：同目录 `RESULT.md`
- 目标：用熟悉的订单业务理解分析查询，作为后续学习 Doris 的起点。

## 场景

假设有一张订单表，每行是一笔订单，`order_id` 唯一：

```text
orders(
  order_id,       -- 订单编号
  user_id,        -- 用户编号，同一用户可以有多个订单
  city,           -- 城市
  amount,         -- 订单金额，十进制定点数
  status,         -- PAID 表示已支付
  created_at      -- 订单创建时间，按北京时间解释
)
```

这里先用简化模型：只统计当前状态为 PAID 的订单，不考虑退款和状态变更历史。按订单创建时间选择数据，而不是支付时间。

业务需求：统计最近 30 个完整自然日，每个城市的已支付订单总金额、订单数，以及下单用户去重数。

为了让结果可复现，本题把时间范围固定为：

```text
2026-08-23 00:00:00（包含）至 2026-09-22 00:00:00（不包含）
```

只返回有符合条件订单的城市，按总金额降序排列，同金额按城市升序排列。

## 今天的三个步骤

1. **区分需求，10 分钟。** 写出两个订单 CRUD 操作和两个统计分析需求；上面的需求可以算其中一个。用自己的话说明区别。
2. **表达查询，20–25 分钟。** 写 SQL 或伪 SQL 实现上面的需求。使用你熟悉的 SQL 方言即可，不要求掌握 Doris 语法。说明订单数和去重用户数是否总相等，为什么。
3. **解释与自查，15–20 分钟。** 对比“按订单 ID 查一笔订单”，说明这个统计查询需要处理哪些数据。如果订单从 1 万增长到 1 亿，你猜测哪个步骤可能增加开销？列出最多两个不确定点。没有执行或测量的判断明确标为猜测。

## 验收标准

- [ ] 能举例区分业务操作与分析需求。
- [ ] SQL 或伪 SQL 表达了时间范围、已支付过滤、按城市分组以及三个统计指标。
- [ ] 能解释订单数与去重用户数的区别。
- [ ] 能说明分析查询和单笔查询的数据处理范围不同，不要求提出优化方案。

不以是否一次写对 SQL 判断能力；暴露不确定点也是有效成果。今天不要求安装 Doris、执行 SQL、阅读源码或提交 PR。
