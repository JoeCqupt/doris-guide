# Step 8：启动 FE，完成第一次连接

- 发布日期：2026-09-23
- 主动投入：30–45 分钟，启动等待另计。
- 目标：启动已构建的 FE，用 MySQL 客户端查看 FE/BE 节点状态。
- 系统位置：查询接入、元数据与集群协调。BE 尚未准备，本步不执行订单建表、导入或扫描查询。

## 已核实的起点

以下为 2026-09-23 发布时的快照：output/fe 已有完整构建产物；当时 doris-meta 为空，mysql 客户端可用，默认 FE 端口未被监听；当时 en0 地址为 192.168.1.119。启动前必须重新检查，不把历史快照当作当前状态。

## 1. 准备运行配置（约 10 分钟）

从已构建的 output 目录运行，修改的是运行配置，不提交到 Git：

```bash
cd /Users/jiangyuan/open/doris/output/fe
cp conf/fe.conf /Users/jiangyuan/doris-guide/step8/fe.conf.before
ipconfig getifaddr en0
lsof -nP -iTCP:8030 -iTCP:8070 -iTCP:9010 -iTCP:9020 -iTCP:9030 -sTCP:LISTEN
```

手动编辑 conf/fe.conf：

- 在原有 JAVA_OPTS_FOR_JDK_17 行仅把 `-Xms8192m -Xmx8192m` 对应两项分别改为 `-Xms1024m`、`-Xmx4096m`（原文件顺序可能相反），保留其他 JVM 参数。4GB 是这次单 FE 本地学习的初始上限，不是生产建议，也不保证后续复杂负载足够。
- 配置 `priority_networks = 192.168.1.119/32`，将地址换成刚刚检查到的实际本机 IPv4。如果 en0 无地址，先反馈，不照抄过期 IP。
- 如果 JAVA_HOME 尚未设置，可在配置中写 `JAVA_HOME=/Users/jiangyuan/dev/jdk-17.0.17.jdk/Contents/Home`；先确认此路径仍存在。
- 当前默认端口：HTTP 8030、RPC 9020、SQL 9030、EditLog 9010、Arrow Flight SQL 8070。如果检查发现被其他进程占用，先记录并反馈，不结束别人的进程。

priority_networks 用于选择 FE 自身地址，不等于限制监听或访问范围。此配置只作为你的本机实验环境。

## 2. 启动并观察（约 10–15 分钟）

```bash
cd /Users/jiangyuan/open/doris/output/fe
bash bin/start_fe.sh --daemon
```

至少等待 30 秒，再查看：

```bash
tail -n 80 log/fe.out
tail -n 80 log/fe.log
lsof -nP -iTCP:9030 -sTCP:LISTEN
```

首次启动慢时继续等待并检查日志，避免反复启动。端口监听只是中间证据，下一步实际 SQL 返回才证明接入可用。若日志报错，把第一个有意义的异常及其 Caused by 附近上下文保存到本任务目录；不要删除 doris-meta 重试。

## 3. 连接并记录节点状态（约 10–15 分钟）

首次本地初始化且尚未设置密码时：

```bash
mysql --protocol=TCP -h 127.0.0.1 -P 9030 -u root
```

若已配置密码则使用 `-p` 交互输入，不把密码写进作答或命令日志。连接后执行：

```sql
SHOW FRONTENDS;
SHOW BACKENDS;
```

记录输出：当前 FE 的 Role、Alive（以实际返回列为准），以及 BE 列表。没有注册 BE 时预期 BE 列表为空；若不同，记录事实，不强行修改成预期结果。

用两句话解释：为什么能连接 FE 并看到节点信息，但还不能据此认为订单表扫描可用了？Step 4 的架构图中，哪部分现在已有运行证据？
